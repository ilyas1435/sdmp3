# v1.10 design — integrated search, auto-spoof, calmer UI, provable background copy

Date: 2026-11-17 · Repo: `/storage/emulated/0/Download/SD-Copy-MP3-Manager`

## Intent / why

Four requests from the operator:

1. Search results must appear **inside the source-file browser** with the same
   row format and behaviour, not in a separate lookalike panel.
2. A general setting must enable timestamp spoofing of the **whole copy
   destination** automatically after every copy.
3. The site's colours/themes must become more varied and easier on the eyes;
   settings must be laid out with **dropdowns** for the font and the colours,
   and icons must be professional SVG everywhere.
4. Copying must provably continue when Chrome is closed while Termux lives,
   with no loss of throughput.

## Goals

- One row renderer for browsing and searching; selecting, excluding, renaming
  and deleting behave identically in both.
- Auto-spoof runs **server-side, in the copy worker**, so it still runs when
  the browser was closed during the copy. Copy statistics remain visible.
- Every palette passes the existing WCAG contract; dropdowns use the existing
  `/api/settings` writer and validation; all icons are SVG.
- The copy queue, its DFS pre-order + `natural_sort_key`, and the single
  sequential writer are untouched.
- All existing gates stay green (py_compile, four self-tests, `bash -n`,
  `node --check` on the rendered single `<script>`, jsdom + backend harnesses).

## Non-goals / anti-goals

- No resume-after-process-death, no durable job queue: the request is
  "Chrome closed, Termux alive", which the current architecture already covers.
- No parallel copying, no per-file `fsync`, no change to `plan_transfer()`,
  `copy_file_sequential()`, `verify_copied_files()` or sync thresholds.
- Auto-spoof never modifies the source tree and never touches protected
  Android/Termux paths; it skips symlinks.
- No remote assets, no new dependencies, no package manifest.
- No removal of existing ids (`selectedCount`, `jocStart`, `settingsPaneIndex`,
  `custom_source_path`, …) and no change to the four settings tabs.

## Constraints

- `project.py` still owns all CSS/HTML/one inline `<script>` inside
  `HTML_TEMPLATE` (plain Python string): every `\` in JS must be doubled in the
  source; one JS syntax error kills the whole UI.
- `sdmp3_state.py` v2 settings are additive only: unknown ids are dropped,
  old files must keep loading, its self-test asserts exact dicts.
- Themes live only in `sdmp3_themes.py` (`_THEME_DEFS`, `BASE_KEYS`); all alpha
  variants and layout tokens are derived in `build_tokens()`. Import raises if
  any `CONTRAST_RULES` pair fails. Text ≥ 7:1 on page/card, muted/labels/kind
  inks ≥ 4.5:1, plus fill-vs-label pairs.
- Every `font-size` is `calc(Npx * var(--font-scale))`; no colour literals
  outside `sdmp3_themes.py`; `font_css`/`app_font` remain `|safe` only inside
  `<style>`.
- Manual spoof uses `/transfer/spoof_only` with `reset_state()` and its own
  thread; do not call it from the copy worker.

## Approaches considered

### Search integration
- **A. Swap the source tree's content into a search view (chosen).** Extract
  `itemRowHtml(item, opts)` from `loadSubFolders()`; `searchDeep()` renders the
  same rows into `#treeContainer`, adds a sticky "search view" header with the
  query, the scope and a «back to browsing» button. Empty query or back
  restores `loadSubFolders(currentSourceRoot, …)`. Folder rows keep their
  `.children` container and `data-toggle`, so expanding a hit loads its real
  children inline exactly as in browsing — it does not leave search or change
  the scope. Mutating a row re-runs the last search. Avoids two competing
  lists and gives byte-identical rows.
- B. Style `#searchResults` to look like the tree. Rejected: the user asked for
  the *same part*, and the two renderers would keep drifting.
- C. Inject result rows above the normal tree. Rejected: mixed views make
  selection/exclusion and rename/delete refresh ambiguous.

### Auto-spoof
- **A. Inline phase in `copy_thread_task` (chosen).** Extract the existing
  bottom-up `os.utime` walk into `spoof_tree(dest, ts, on_progress,
  cancelled, skip_roots)`; the manual route reuses it. After verification and
  before the final `finish_transfer`, if `APP_SETTINGS['auto_spoof']` and the
  copy was not cancelled, run the helper with `touch_progress()` per entry,
  generate the timestamp server-side (random day in 2023, matching the UI),
  and add `phase/spoof_total/spoof_done/spoof_error/spoof_cancelled` to the
  *same* final state so no copy number is lost. `finish_transfer` is called
  exactly once. If spoofing fails or is cancelled, the copy stays `done` and
  the warning is carried in `spoof_error`/the final message — the files were
  copied successfully. The worker already holds the wakelock and
  `ACTIVE_THREAD`. The helper skips symlinks, any selected source path, and
  protected paths refused by `protected_target_reason()`; the setting's hint
  says «كل الوجهة ما عدا مسارات المصدر والمجلدات المحمية».
- B. POST `/transfer/spoof_only` from the JS completion handler. Rejected:
  it would not run with Chrome closed (requirement 4) and `reset_state()`
  would erase the copy result.
- C. Start a second backend thread after copy. Rejected: wakelock release and
  `ACTIVE_THREAD` are not refcounted; races with the copy's `finally`.

### Themes / settings / icons
- **A. Recolour all 14 palettes (including the default, per the operator's
  choice), add two new ones, replace the theme and font card grids with two
  labelled selects, add sprite symbols for the remaining glyph icons
  (chosen).** The default id `coffee-blues` stays the default; its hexes change
  while the documented character (warm sand text on cool slate, teal marks,
  calm sage/rose semantics) survives. AGENTS.md is updated: no palette stays
  byte-identical. The four-preset font-size control stays a segmented control
  — only the font family and the colours were asked for as dropdowns. Dropdown
  options keep `data-theme-id` / `data-font-id` / `data-size-id` so validation
  and existing handlers stay simple; `pickTheme`/`pickFont`/`pickFontSize`
  keep their signatures and POST bodies.
- B. Add themes but keep the old palettes. Rejected by the operator's answer.
- C. Keep the card grids and only restyle them. Rejected: dropdowns requested.

### Background copy
- No engine change: `sdmp3 start` already uses `start_new_session=True`,
  stdin `/dev/null`, stdout → log; `app.run(threaded=True, debug=False)`;
  the worker is a daemon thread with no Flask request context, no session and
  no client-driven tick. Cancellation is explicit only; heartbeats are
  maintained in the worker. Add: guard `release_wakelock()` with
  `WAKELOCK_ENABLED`, expose `worker_alive` in `/transfer/status`, show a calm
  "يستمر النسخ في الخلفية" note in the progress modal, and add a harness test
  that starts a copy and performs **zero** status polls until it finishes.

## Implementation outline

1. **State/settings** (`sdmp3_state.py`, `project.py`): additive `auto_spoof`
   bool in v2 (load/save/self-test/APP_SETTINGS/POST coercion), rendered in
   the General pane; the saved value is the consent, so no per-copy prompt.
2. **Search** (`project.py`): shared row renderer; search-view state
   (`lastQuery`, `lastFoldersOnly`, `treeInSearchMode`); `/api/search` returns
   `size` for file hits (stat at most 40 matches — no new stat in the cache
   build); history recording and cache badge unchanged.
3. **Spoof** (`project.py`): `spoof_tree()` helper used by both the manual
   route and the copy worker; server-side random date helper; combined final
   state and UI summary.
4. **Look**: palette updates (`sdmp3_themes.py`), settings selects + field
   layout, 5 new sprite symbols and glyph replacement in template/JS.
5. **Background**: wakelock guard, `worker_alive` snapshot field, UI note,
   no-polling harness proof.
6. **Docs/gates**: update AGENTS.md/README.md/VERSION to 1.10.0; run every
   gate including the single-script `node --check`, jsdom and backend tests.

## Risks / mitigations

- Palette edits may break contrast → run `python sdmp3_themes.py` first; fix
  hexes until the module prints "all contrast rules satisfied".
- One bad JS token kills the UI → regenerate `/` and run `node --check` after
  every JS edit, then jsdom.
- Auto-spoof on a volume root touches pre-existing files → document it in the
  setting's hint and in the final summary; it never touches the source tree.
- Search rows share `.checkbox[value=path]` with the tree, but only one view
  is mounted at a time; `refreshCheckboxStates()` stays harmless.
- Renaming/deleting from a search result must re-run the search, not reload
  the directory (which would drop the search view).
- No new file writes in the copy loop; auto-spoof metadata writes happen only
  after the final flush and verification, single-threaded.

## Left to the builder

Exact hex values, select CSS measurements, icon path data, and the precise
wording of Arabic labels are builder choices as long as every gate passes and
the visual result stays calm, varied and self-contained.
